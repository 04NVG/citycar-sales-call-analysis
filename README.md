# Разбор звонков отдела продаж: LLM извлекает, код проверяет

**Демо:** https://citycar-sales-call-analysis.vercel.app

Проект сделан в рамках тестового задания CityCar (AI-оператор / AI-агент). Полный ответ на задание (архитектура, human-in-the-loop, риски) лежит в [citycar_answer.md](citycar_answer.md). Здесь — работающий код ключевого шага этой архитектуры: разбора звонка.

## Идея

LLM читает транскрипт звонка и заполняет строгую JSON-схему: итог, следующий шаг, квалификация, возражения, чек-лист скрипта, риски. Каждый вывод ссылается на дословную цитату с таймкодом. После этого результат проверяет обычный код:

1. **Схема.** Pydantic отклоняет ответ, если вывод ссылается на несуществующую цитату.
2. **Цитаты.** Каждая цитата должна дословно найтись в реплике того же спикера рядом с указанным временем. Если не нашлась, вывод уходит на ревью.
3. **Сверка с CRM.** «В разговоре договорились о следующем шаге, а открытой задачи по сделке нет» — это добавляет код, не модель.
4. **Маршрутизация.** Непроверенная цитата, низкая уверенность или серьёзный риск означают, что разбор проверит человек. Выводов о сотрудниках система не делает.

## Состав

| Файл | Что делает |
|---|---|
| `amo_leads_attention.py` | Код для п. 3 задания (48 строк): через amoCRM API v4 находит открытые сделки без открытых задач или с просроченными задачами. Обходит пагинацию, повторяет запрос при 429, обрабатывает ответ 204. |
| `call_analysis.py` | Схема `CallExtraction` (её заполняет LLM) и `CallAnalysis` (метаданные и решение о ревью, их добавляет код), плюс детерминированные проверки. |
| `llm.py` | Единственный вызов LLM: Claude API, structured output по Pydantic-схеме, обработка отказов и ошибок. |
| `transcript.py` | Разбор транскрипта `[мм:сс] Менеджер: текст` в сегменты, как их отдаёт STT с диаризацией. |
| `demo_samples.py` | Три синтетических звонка и сохранённые разборы для демо без API-ключа. |
| `api/index.py` | FastAPI: `/api/health`, `/api/samples`, `/api/analyze`. Ограничения на длину транскрипта и частоту живых запросов. |
| `public/index.html` | Интерфейс на чистом HTML/JS. На каждом блоке видно, что заполнила модель (LLM), а что посчитал код (КОД). |
| `tests/` | 12 тестов: amoCRM на моках, схема, проверка цитат, сверка с CRM, API. |

Стек: Python 3.12, FastAPI, Pydantic, Anthropic SDK (structured outputs), pytest, Vercel Functions.

## Запуск

```bash
pip install -r requirements-dev.txt
pytest -q

# живой режим локально или на Vercel: нужен ключ
export ANTHROPIC_API_KEY=...
# опционально: ANTHROPIC_MODEL (по умолчанию claude-opus-5-5), ANTHROPIC_EFFORT (по умолчанию low)

# поиск сделок в amoCRM
export AMO_SUBDOMAIN=yourcompany AMO_TOKEN=...
python -c "from amo_leads_attention import leads_needing_attention as f; import json; print(json.dumps(f(), ensure_ascii=False, indent=2))"
```

Без `ANTHROPIC_API_KEY` демо показывает сохранённые разборы, а проверки (цитаты, сверка с CRM, маршрутизация) выполняются по-настоящему. Если отредактировать транскрипт, проверка цитат это заметит.

## Что проверено и что нет

- Эндпоинты amoCRM, фильтры, лимиты и формат ответа сверены с документацией API v4. Код проверен на моках, на реальном аккаунте его не запускали.
- Звонки синтетические. Сохранённые разборы сгенерированы Claude в той же схеме и проходят те же проверки.
- Это демо одного шага архитектуры, а не продакшен. Нет STT по аудио, хранилища, очередей и авторизации: они описаны в архитектуре, но в демо не реализованы.
- Лимит живых запросов хранится в памяти одного инстанса функции и защищает только частично. Для публичного ключа задайте лимит расходов в консоли Anthropic.
