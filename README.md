# CityCar: анализ работы отдела продаж (amoCRM + телефония)

Решение тестового задания на позицию AI-оператор / AI-агент. Полный ответ (архитектура, human-in-the-loop, риски) лежит в [citycar_answer.md](citycar_answer.md).

## Что в репозитории

| Файл | Что делает |
|---|---|
| `amo_leads_attention.py` | Фрагмент кода (48 строк) для п. 3 задания: через amoCRM API v4 находит открытые сделки без открытых задач или с просроченными задачами. Обходит пагинацию, повторяет запрос при 429, обрабатывает пустой ответ 204. |
| `call_analysis.py` | Pydantic-схема результата анализа звонка (JSON Schema для structured output LLM) и детерминированные проверки: каждая цитата должна существовать в транскрипте, обещанный следующий шаг сверяется с задачами в CRM, по правилам решается, что уходит человеку на ревью. |
| `tests/` | Тесты на замоканном API amoCRM и на синтетическом звонке. |

Вызова LLM и STT здесь нет намеренно: показана граница между моделью и кодом. Модель заполняет `CallAnalysis`, а всё, что можно проверить без модели, проверяет код.

## Запуск

```bash
pip install -r requirements.txt
pytest -q

# на реальном аккаунте:
export AMO_SUBDOMAIN=yourcompany
export AMO_TOKEN=...   # долгосрочный токен приватной интеграции или OAuth access token
python -c "from amo_leads_attention import leads_needing_attention as f; import json; print(json.dumps(f(), ensure_ascii=False, indent=2))"
```

## Что проверено и что нет

- Эндпоинты, фильтры, лимиты и формат ответа сверены с документацией amoCRM API v4 (`/api/v4/leads`, `/api/v4/tasks`; `limit` ≤ 250; 7 запросов/с на интеграцию).
- Код проверен только на моках, на реальном аккаунте amoCRM его не запускали.
- Задачи, поставленные не на сделку, а на её контакт, не учитываются. Учитывать ли их, решает бизнес.
